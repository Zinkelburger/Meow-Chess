Priority issues

1. P1 — Preserve unfinished work and make Close/Escape predictable.

In lib/ui/players_view.dart, PlayerPanel field changes update local state; commit happens on submit or close. Parent page/section navigation replaces the child without persisting its draft. A partly typed walk-up or player edit can disappear. Conversely, closing a valid Add player draft calls commit and creates the player; an invalid draft can prevent closing. Escape uses the same close callback. The new global Saved indicator cannot mean that every visible form value is durable.

Persist drafts separately from committed event data, including invalid partial input. Keep Add as the explicit creation action. Close/Escape should safely leave the draft; expose a separate Discard draft action. Distinguish “Event saved” from “Draft saved” or a failed draft save. Preserve the results board, side, search and scroll when returning, while reopening historical rounds read-only and explicitly resetting on a newly posted round.

Evidence: players_view.dart PlayerPanelState.commit/close/dispose and field onChanged; workspace.dart go/pickSection and section-keyed view construction; results_view.dart:86–119 and remember() persist only missingOnly. The “interrupted drafts” test at test/infrastructure/storage_test.dart:128 writes a synthetic preference directly; it does not prove the actual form recovers.

Acceptance: type a partial walk-up, switch sections, return, restart, and recover the draft without adding anyone. Enter several results, answer a lookup in another section, return to the same board/side. Committed results must remain intact.

2. P1 — Make printing match the round and revision the TD expects.

ResultsView's Print packet passes an event and section, but no selected round. reportPdf chooses each section's last round. Thus browsing round 1 after round 2 is posted still prints round 2. PrintPanel also caches a PDF generated from the event snapshot supplied when opened; the event can subsequently change alongside the dock without the panel warning that its output is older.

Pass an explicit print scope containing section, round and revision. Label it above the preview. Keep an older preview visibly marked “Out of date — refresh” after corrections, and require a deliberate choice to print an older revision. Do not silently switch the user's preview. Add a Retry action for generation failure.

Evidence: lib/ui/results_view.dart Print packet callback; lib/ui/panels.dart:688–699 and showPrint(); lib/infrastructure/reports.dart:119.

Acceptance: viewing round 1 prints round 1; correcting a score with the preview open shows its stale status; refreshing generates the corrected revision. Printer cancellation preserves scope and tournament data.

3. P1 — Finish panel coordination and test the whole workspace at large text.

Credit 45eadff for making Event details and the general dock mutually exclusive. History remains independently open, and player details have their own inner panel. A lookup/print dock and History can still consume most of a laptop's width. Existing screenshots show the board table horizontally constrained with lookup open. The fixed-height selection action bar is another large-text risk, especially while the spacing pass increases padding.

Use one coordinated contextual panel system with a minimum usable table width and predictable focus restoration. Adapt widths to the window and text scale. Make action rows grow vertically rather than forcing larger text into fixed heights. Validate before mechanically snapping all spacing values.

Evidence: workspace.dart independent dock/history branches; players_view.dart PlayerDetailsLayout and _selectionBar; panels.dart 480px lookup/print docks. These are source-backed risks, not newly reproduced overflows.

Acceptance: at 1280×720 and 200% text, keyboard users can find, edit, score, undo and print without hidden required actions or focus traps, with long names and history/lookup transitions.

Persona and cognitive-load findings

A solo TD's largest risk is being interrupted while typing or scoring and returning to a different context. A relief TD needs actionable issues and reliable output revision labels. A keyboard/screen-reader user still needs a complete focus and semantics pass, especially bulk-selection names. The screen now communicates rounds better, but dense shortcut legends, class chips and competing panels still demand attention. Keep the live scoring path simple and progressively reveal uncommon operations.

The emotional high point is fast, reversible result entry. The weak moments are returning after an interruption and deciding whether the printout, backup and report reflect the latest corrections. These moments need explicit state and recovery actions, not more decoration.
